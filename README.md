# E-Hub

Google AI Studioから引き継いだReact / Express / SQLiteアプリです。
今後の作業フォルダは `/Users/yamatotatsunori/Documents/ChatGPT/E-hub` です。

## 起動

Node.js 22以降を使用します。

```sh
cd /Users/yamatotatsunori/Documents/ChatGPT/E-hub
npm install
npm run dev
```

ブラウザで http://localhost:3000 を開きます。

## 設定

サーバーはこのフォルダの `.env.local`、`.env` の順に読み込みます。
`OPENAI_API_KEY` は設定済みで、ブラウザへの配布対象外です。
テキストモデルは `OPENAI_MODEL`、画像モデルは `OPENAI_IMAGE_MODEL` で変更できます。
初期値はそれぞれ `gpt-6-astra`、`gpt-image-2.5-flare` です。
契約文生成、スカウト、アイデアの整理・相談、翻訳、画像生成はOpenAIを使います。
Google OAuth・Firebase・StripeはAI以外の既存機能として残しています。利用には別途各サービスの設定が必要です。

### Profileの名刺

Profileの上部で名刺を作成・登録できます。右上のQRボタンで自分のQRコードを表示し、その画面から相手のQRコードをカメラまたは画像ファイルで読み取ります。読み取った相手はフォロー中と「取り込んだ名刺」に追加され、一覧から相手のProfileを開けます。同じQRコードを繰り返し取り込んでも、フォローと名刺は重複しません。端末のカメラアプリでQRリンクを開いた場合は、相手のProfileから取り込めます。

右下の名刺ボタンでは、氏名・会社・役職・連絡先とデザインを入力して作成するか、紙の名刺を撮影／画像選択して登録します。写真の文字の自動認識は行いません。氏名・会社などは入力して登録してください。登録した名刺と連絡先は、本人と、本人がフォローしている相手または本人をフォローしている相手にのみ表示されます。未登録の名刺枠は表示せず、本人には作成・登録とQRの操作だけをコンパクトに表示します。

カメラは初回の利用許可が必要です。HTTPS（開発時はlocalhost）で利用し、カメラが使えない端末では画像選択を利用できます。画面を閉じる、撮影が完了する、QRを取り込む、別タブに移動するとカメラを停止します。別タブから戻った場合は再起動ボタンで再開できます。

名刺はSQLiteの `business_cards`、交換先は `collected_business_cards` に保存します。テーブルは起動時に追加します。名刺APIの利用者指定には既存アプリと同様にユーザーIDを利用しており、公開運用時の認証基盤の置き換えは別途必要です。

`npm run test:cards` は独立した一時DBを使い、既存API・ワークフロー、名刺の保存、QR交換、重複防止、カメラの疑似映像・拒否・停止、スマホ／PCの画面表示を検証します。実機カメラの画質・権限操作は端末での確認が必要です。

### フォロー中から取り込んだ名刺を確認

自分のProfileの「フォロー中」を開くと、「フォロー中」と「取り込んだ名刺」をタブで切り替えられます。名刺タブにはQR交換で名刺を取り込んだユーザーを表示し、選択するとそのユーザーのProfileと名刺を確認できます。タブは左右キーでも切り替えられます。通信失敗時は再読み込みでき、タブ切り替え前の応答は一覧へ反映しません。

写真登録は縦型・横型ともに元画像の比率を維持して全体を表示し、画面が低い場合は表示高さも縮めます。デザインメーカーも「名刺の向き」で横型91:55／縦型55:91を切り替えられます。向きは表裏に共通で、保存・再編集・Profile表示・名刺交換後の一覧にも反映します。切り替えでは文字や画像を保持し、はみ出す要素は縮小して位置を調整します。変更前の配置へ戻すには「戻る」を使ってください。向きの情報がない以前の名刺は横型として開きます。

### 自分のVisionの編集・削除

Vision一覧・詳細の自分の投稿にある「…」から編集と削除を行えます。編集では本文と画像（最大4枚）を変更し、引用元・返信・Like・保存を維持します。「編集済み」を表示し、Projectの引き継ぎ元カードと引用カードも最新の本文・画像を表示します。通信に失敗した場合は入力を保持して再試行できます。

削除は確認画面を経て行い、元の本文・画像・返信と、その投稿へのLike・保存を削除します。引き継ぎ先のProjectと他の引用投稿は削除せず、「元のVisionは削除されました」と表示し、削除済みのカードにはリンクを設けません。削除済み識別用のID・種類・日時のみを残し、本文や画像は保持しません。自分の引用投稿も編集・削除でき、引用元の件数に反映します。別タブで開いた参照先も更新通知で再取得します。

`npm run build` 後、`node tests/run-validation.mjs --vision-manage` で、一時DB上のスマホ相当3サイズ（320×568、390×844、844×390）・PC2サイズ（1024×768、1440×900）で編集・画像追加／削除・再編集・削除キャンセル／確定・失敗時の再試行・参照先の即時反映と再読み込み後の保持を検証します。旧Idea系Visionも対象に含め、他人の投稿とProjectを変更できないこともAPIで確認します。

### 自分の返信・返信への返信の編集と削除

Vision詳細の自分の返信にある「…」から編集・削除できます。編集では本文だけを変更し、元の返信先と子の返信を維持して「編集済み」を表示します。空の本文は保存できず、通信失敗時は入力を残して再試行できます。

返信を削除すると本文を消去します。子孫に残っている返信がある場合は「この返信は削除されました」と表示して会話のつながりを維持し、子孫もなくなった削除済みの枝は非表示にします。削除済みの返信は一覧・詳細・返信タブの件数に含めません。削除済みの返信を新しい返信先にすることもできません。返信入力中に返信先が削除された場合は、古い本文を表示せず、下書きを保持して送信を無効にします。別タブのタイムラインと詳細は更新通知で再取得します。

`npm run build` 後に `node tests/run-validation.mjs --reply-manage` を実行すると、スマホ相当3サイズ・PC2サイズで親／子の返信の編集・再編集・削除、他ユーザーの孫返信の保持、件数の同期、再読み込み、削除キャンセルと通信失敗後の再試行、他人の返信を操作できないことを検証します。

### Visionの一連操作を通した検証

`npm run build` 後の `node tests/run-validation.mjs --vision-lifecycle` は、同じ画像付きVisionをUIから投稿し、Projectへの引き継ぎ・元投稿への復帰・引用・親／子の返信の編集と削除・別ユーザーの孫返信の保持までを続けて検証します。さらに元のVisionを編集・削除して、Projectと引用投稿の本文を維持し、引用側の返信を引き続き編集・投稿・削除できることを確認します。各段階で件数・返信先・再読み込み後の表示・はみ出しと操作性を確認し、スマホ相当3サイズとPC2サイズで実行します。

### Projectの募集・提案の編集と削除

自分が作成した募集・提案の詳細にある「投稿の管理」から、タイトル・本文・画像を編集、または確認画面を経て削除できます。タイトルだけの編集では元の本文の書式も維持します。編集後も引き継いだVision・公開範囲・返信の親子関係・Like・保存を維持し、「編集済み」を表示します。

削除した投稿の本文・画像・返信は表示せず、一覧・プロフィール・検索から除外します。引き継ぎ元のVisionや別の提案・引用投稿は残り、参照カードは「元のProjectは削除されました」と表示してリンクを外します。Projectの行は削除状態として残し、別の投稿や履歴レコードへの連鎖削除を避けます。削除先への新しい返信・提案と、古い画面からの更新は拒否します。

`npm run build` 後、`node tests/run-validation.mjs --project-manage` で、募集はスマホ相当3サイズ・PC2サイズ、提案はスマホとPCの各1サイズで検証します。編集・再編集・削除・通信失敗後の再試行、3階層の返信と件数、別タブへの反映、元Visionが先に削除された場合、再読み込み後の表示まで確認します。

Visionの操作列は一覧・詳細とも、左から「返信（コメント）・引用・Like・保存」の順です。詳細のリンクコピーはヘッダーにあります。`--vision-social` の検証では順序と同じ行での配置も確認します。

### Visionの4操作の順序・操作・状態保持

### Projectのライト表示

募集・提案の一覧／詳細、履歴カード、関連提案、ステージ表示、参加申請・共有・メンバー追加・閲覧許可ユーザー・履歴などのパネルは白と薄いグレーを基本にします。写真のタイトル帯も白背景と濃い文字で表示し、以前のテーマ設定やOSのダーク設定が残っていてもライト表示を維持します。

### Vision・Project共通の下書き

Visionの投稿画面、Projectの募集／提案作成画面の「下書き一覧」から、左側のサイドバーを開きます。共通ヘッダーには下書きボタンを置きません。Visionの投稿画面にはVisionの下書きだけを、Projectの募集・提案作成画面にはProjectの下書きだけを表示します。保存した下書きを選ぶと投稿画面を再開できます。削除には確認操作があります。

Visionの投稿画面とProjectの作成画面にある「下書きに保存」で、本文・画像・引用先・募集／提案の区分・公開範囲・引き継ぎ元のVisionを保存します。保存時点では投稿されません。下書きから再編集して投稿すると、成功したものだけ一覧から取り除きます。保存・投稿に失敗した場合は入力内容を保持します。

新しい下書きはユーザー別にSQLiteの `post_drafts` に保存します。以前の端末内下書きは削除せず、保存済みのものがある場合にサイドバーの「以前の端末内下書きを開く」から利用できます。アカウント切り替え時には編集中の下書き画面も切り替わります。

`npm run build` の後、`node tests/run-validation.mjs --drafts --sections` で一時DBを使って検証できます。320×568、390×844、844×390、1024×768、1440×900で、画像付きVision・引用・Projectの募集／提案の保存／再開／再編集／投稿／削除、失敗時の保持、再読み込み、他のユーザーからのアクセス拒否を確認します。
